# РУССКИЙ ЯЗЫК ЕГЭ — РЕГЛАМЕНТ ДЕМОВЕРСИЙ: СОЧИНЕНИЕ, ПРОВЕРКА И РЕЗУЛЬТАТ

**Статус: обязательный предметный регламент для всех годов интерактивной демоверсии ЕГЭ по русскому языку.**  
База фиксации: проверенная реализация 2026 v4.2, 15 августа 2026 года.

Этот документ фиксирует архитектурные и UX-правила, которые нельзя снова изобретать при подготовке 2025, 2024 и последующих годов. При этом **цифры, критерии и официальные основания всегда заново сверяются с комплектом конкретного года**.

## 0. ЖЁСТКИЙ PATCH-ONLY SCOPE ДЛЯ УЖЕ ОПУБЛИКОВАННЫХ 2025–2022

Версии ЕГЭ по русскому языку **2025, 2024, 2023 и 2022 уже созданы, работают и опубликованы на Эксамио**. Они не являются заготовками для пересборки.

Для этих четырёх лет запрещено без отдельного прямого поручения пользователя:
- перепроверять или переписывать задания 1–26 «ради стандарта»;
- менять условия, ответы, варианты, scorer или нормализаторы;
- менять таймер, навигацию, автосохранение, порядок заданий или механику попытки;
- менять SEO, HEAD, URL, canonical, дизайн страницы, рекламу, шапку или футер;
- переносить в них данные, критерии, максимумы и формулировки 2026 года вместо уже существующих годовых данных;
- проводить общую модернизацию, рефакторинг или пересборку рабочих версий.

Разрешены **ровно две зоны изменений**:
1. первый экран демоверсии («Перед началом» и примыкающий ученический текст об источнике) — привести к понятной лаконичной подаче 2026 без технической служебщины и без чрезмерного акцента на ФИПИ;
2. работа с сочинением после завершения попытки — перенести зафиксированные в 2026 UX/механические улучшения этого регламента, но использовать **только уже действующие критерии, шкалы, зависимости, пороги и максимумы конкретного года**.

Перед изменением каждого года обязательно снять исходные hashes/копии затрагиваемых файлов. После изменения доказать, что всё вне этих двух зон осталось неизменным. Предпочтение отдаётся минимальному точечному patch/add-on вместо изменения рабочего ядра.

## 1. Что переносится между годами, а что нет

Можно использовать как технический паттерн после source gate:
- два режима сочинения: бумага / ввод на сайте;
- отдельный post-exam review-state;
- явная кнопка запуска проверки;
- multipage scan/zoom;
- раскрываемые подсказки по критериям;
- разделение автоматической части, оценки сочинения и общего displayed result;
- reset/persistence/privacy invariants.

Нельзя переносить без новой сверки:
- число заданий и время;
- максимумы баллов;
- формулировки К1–К10 и их шкалы;
- каскады критериев;
- порог слов и основания полного нуля;
- официальный текст задания 27 и исходный текст;
- storage/version keys без нового year/version namespace.

## 2. Язык интерфейса ученика

Интерфейс пишется простым русским языком. В student UI запрещены внутренние слова `confirmed`, `possible`, `findings`, `hard cap`, названия storage keys и служебные объяснения архитектуры.

Не создавать «культ источника»: достаточно коротко указать основу демоверсии и ссылку на источник. Технические/юридические оговорки не должны заслонять действие ученика.

Допустимые student labels:
- «Найдены ошибки»;
- «Стоит проверить»;
- «Проверить текст»;
- «Как оценивать»;
- «Ваш результат».

## 3. Во время экзамена

В режиме ввода сочинения на сайте:
- отключить browser spellcheck, autocorrect, autocomplete, autocapitalize и сторонние writing suggestions;
- текст автосохраняется;
- до завершения экзамена не показывать результаты анализа/правильные ответы;
- после finish текст фиксируется read-only и не должен изменяться из-за последующей мутации core state.

В бумажном режиме:
- во время экзамена хранится только факт выбора режима/готовности;
- после finish появляется ручной перенос текста и возможность приложить локальные страницы.

## 4. Фото и сканы

После finish в paper mode:
- кнопка выбора файлов должна быть заметной, не системно-бледной;
- поддержать несколько страниц за один выбор и последовательное добавление;
- показывать все страницы;
- каждое изображение открывается крупно; обязательны `+`, `−`, «По размеру», «Закрыть», `Esc`;
- PDF можно открыть отдельно;
- фото/сканы остаются локальными и не отправляются в spelling API;
- если файлы не сохраняются через reload, прямо не обещать обратного; после reload допускается повторное прикрепление.

## 5. Когда запускается проверка

**Только после явного нажатия «Проверить текст».**

Пока ученик печатает/перепечатывает:
- сохранять текст;
- обновлять технический счётчик слов;
- не запускать эвристический анализ;
- не создавать findings;
- не менять баллы К7–К10.

Если текст изменён после проверки:
- analysisStatus → pending;
- прежние К7–К10 findings и выставленные по ним scores очищаются/инвалидируются;
- UI снова предлагает нажать «Проверить текст».

## 6. Автоматический слой К7–К10

Автоматическая проверка — только учебный advisory layer.

Внутренняя модель может иметь уровни confirmed/advisory/technical, но student UI их внутренними именами не показывает.

Обязательные ограничения:
- контекстно-зависимая эвристика не создаёт confirmed автоматически;
- advisory не снижает максимальный балл;
- technical не относится к К7–К10 и не влияет на балл;
- отсутствие отмеченных мест не означает отсутствия ошибок и не выставляет максимальный балл;
- confirmed cap разрешён только при отдельной однозначной validation path и только если это соответствует критериям данного года.

Визуально:
- непустой «Найдены ошибки» → светло-красный + красный акцент;
- непустой «Стоит проверить» → светло-жёлтый + оранжевый акцент;
- пустые блоки остаются нейтральными.

## 7. Внешняя орфографическая проверка

Если используется Яндекс.Спеллер:
- запрос выполняется только после кнопки;
- ученик до/рядом с кнопкой видит, что текст будет отправлен в Яндекс.Спеллер для проверки орфографии;
- фото/сканы туда не отправляются;
- выполнить обязательную атрибуцию «Проверка правописания: Яндекс.Спеллер» с активной ссылкой в соответствии с условиями сервиса;
- внешние кандидаты остаются advisory;
- сбой внешнего сервиса не должен ломать локальную проверку и самооценку;
- status не должен обещать «ошибок нет». При нуле: «Система ничего не отметила. Это не означает, что ошибок точно нет».

Статус внешней проверки должен быть привязан к идентификатору текущей попытки (`startedAt` или эквивалент). Новая попытка не наследует `complete/checking/failed` предыдущей.

## 8. Подсказки К1–К10

У каждого критерия есть раскрываемая «Как оценивать».

Текст подсказки:
- строится по официальной шкале конкретного года;
- объясняет ученику, когда ставить каждый балл;
- не превращается в шаблонный одинаковый абзац для всех критериев;
- не подменяет официальный criterion gate эвристикой.

Если официальный критерий задаёт зависимость (например, К1 → К2/К3), она enforced и в UI, и в scorer.

## 9. Общие основания нуля и счётчик слов

Технический счётчик слов — ориентир, не автоматический официальный вердикт.

Основания полного нуля, порог слов и иные gates берутся **только из документов нужного года**. Не вычислять официальные основания примитивной эвристикой.

## 10. Итог ученика

После автоматической проверки закрытой части показывается её первичный балл.

После заполнения всех критериев сочинения показывается общий **учебный результат за всю работу**:

`балл заданий закрытой части + оценка сочинения = итог / официальный максимум года`

Рядом обязательно указать составляющие и что часть за сочинение основана на оценке пользователя, например:
`Задания 1–26: 24 + сочинение: 18 (по вашей оценке)`.

Не держать ученика на экране с «—/общий максимум», если он уже полностью оценил сочинение.

## 11. State и новая попытка

Нужны раздельные namespaces для core attempt, Task27 review и external-check status.

Новая попытка обязана очистить:
- writing mode;
- paper-completed;
- frozen/transferred text;
- zero reasons;
- criterion scores;
- findings;
- external spelling status.

Reload текущей running/finished попытки, наоборот, должен сохранять корректное состояние.

## 12. Обязательные regression cases

Для каждого года добавить browser/unit tests минимум на:
1. finish без автоматического анализа сочинения;
2. typing paper transfer → zero findings;
3. explicit button → analysis complete;
4. edit after check → analysis pending + К7–К10 invalidated;
5. новая попытка не наследует review/spelling state;
6. multipage upload + zoom каждой страницы;
7. advisory/error highlighting only when non-empty;
8. внешний spelling candidate не становится confirmed;
9. contextual repetition не confirmed автоматически;
10. technical formatting note не режет балл;
11. K1/dependency tampering;
12. все zero gates конкретного года;
13. все K1–К10 help blocks;
14. whole displayed result = short + essay self-assessment;
15. mobile widths и no horizontal scroll;
16. console errors = 0.

## 13. Release gate

До GO:
- source/year passport подтверждены;
- runtime manifest актуален;
- все tests PASS;
- installation содержит фактическое число T123;
- after-publish checklist соответствует текущей архитектуре.

LIVE GO — только после проверки фактически опубликованной страницы.
