# ПРИЁМОЧНЫЙ РЕГЛАМЕНТ ИНТЕРАКТИВНЫХ ДЕМОВЕРСИЙ ЕГЭ ПО МАТЕМАТИКЕ

> **ОБЛАСТЬ ПРИМЕНЕНИЯ: ЕГЭ ПО МАТЕМАТИКЕ — БАЗОВЫЙ И ПРОФИЛЬНЫЙ УРОВНИ.**
> Этот регламент действует вместе с `/00-SOURCE-FIDELITY-ZERO-TOLERANCE.md`. При любом конфликте более строгий zero-tolerance запрет имеет приоритет.

Дата редакции: 17 августа 2026 года.

## 1. Главный принцип

Демоверсия не считается проверенной по факту наличия тестов, правильных ответов в JavaScript, отсутствия ошибок консоли или визуального просмотра нескольких заданий.

Для каждого официального примера должна существовать доказуемая цепочка:

`год → уровень → № задания → № официального примера → официальный PDF → страница → точный текст/начертание → формула/таблица/рисунок → требуемое действие ученика → фактический контрол → официальный ответ/критерий → browser-test → результат`.

Если цепочка неполна, пример считается **НЕ ПРОВЕРЕН**.

## 2. Источник истины и годовой source lock

Для каждого года используются только официальные материалы соответствующего года:

- демонстрационный вариант;
- спецификация;
- кодификатор;
- справочные материалы;
- ответы и критерии, входящие в официальный комплект.

До любого извлечения содержания и до копирования кода из другого года обязательны:

1. фиксация точных имён исходных файлов;
2. фиксация года и уровня;
3. SHA-256 каждого официального файла;
4. карта physical PDF page → printed page/half, если исходник двухполосный или имеет нестандартную раскладку;
5. lock количества заданий, официальных примеров, времени и максимального балла по спецификации/демоверсии.

Пакеты 2024/2025/2026, JavaScript соседнего года, сторонние сайты и память исполнителя **не являются источником содержания** для 2023/2022. Разрешено повторно использовать только технический каркас после source lock текущего года.

## 3. Audit matrix

Для каждого официального примера должна существовать строка audit-matrix. Минимальные поля:

`year, level, task, official_variant, pdf_file, pdf_sha256, pdf_page, source_text_checked, typography_checked, formula_checked, table_checked, visual_checked, visual_ui_crop_checked, source_visual_ref, implementation_file, required_control, actual_control, interaction_checked, correct_answer, alternatives_checked, scorer_checked, autosave_checked, reload_checked, result, defect_id, evidence`.

`PASS` запрещён, если применимое поле не подтверждено фактически.

## 4. Текст и типографика

Каждый официальный пример сверяется с PDF по фактическому отображению, а не по смыслу. Проверяются буквы, цифры, знаки, единицы, кавычки, тире, скобки, индексы, степени, жирное/курсив/подчёркивание, подписи А–Б–В–Г, номера, заголовки и подписи.

Добавленное от себя слово внутри условия — дефект, если оно не отделено явно как интерфейсная подсказка Эксамио.

## 5. Формулы

Формула проверяется семантически и визуально. Нельзя считать формулу проверенной только потому, что LaTeX/MathML валиден или математически эквивалентен источнику.

Если text extraction теряет знак, индекс, корень, дробь или структуру, используется точный source crop официального PDF либо иной способ, который сохраняет официальное начертание без реконструкции.

## 6. Визуалы: только официальный источник

Если официальный PDF содержит рисунок, график, схему, чертёж, диаграмму, таблицу-изображение или иной значимый визуальный фрагмент, разрешены только:

- render официальной PDF-страницы;
- direct contiguous crop нужного фрагмента;
- поворот;
- безопасный resize без изменения содержания;
- техническая PNG/WebP-конвертация без изменения содержания.

**Запрещены:** SVG/Canvas/HTML-реконструкции официального визуала, ручная перерисовка, восстановление по смыслу/ответу, «улучшение» геометрии, подписей, масштаба или композиции.

Старая формулировка «реконструкция допустима при технической необходимости» отменена. Если source crop получить нельзя — `VISUAL_GATE = FAIL`.

## 7. VISUAL UI CROP GATE — отдельный от source fidelity

Попиксельное происхождение из PDF само по себе ещё не означает хороший интерфейсный crop. **Каждый visual asset проверяется индивидуально в контексте конкретного задания и конкретного официального примера.**

Для каждого asset обязательно фиксируются и проверяются:

- task/official variant/asset ID;
- официальный PDF + SHA-256 + printed page;
- точный crop rectangle;
- четыре края crop;
- оси координат целиком;
- подписи осей;
- деления и числовые отметки;
- единицы измерения;
- легенда;
- подписи точек, вершин, сторон, размеров и геометрических объектов;
- отсутствие обрезанного смыслового элемента;
- отсутствие лишнего соседнего текста/таблицы/характеристик, которые должны быть отдельным элементом интерфейса;
- читаемость desktop и mobile;
- требуемая интерфейсная ширина;
- необходимость zoom.

Нельзя применять один универсальный crop-паттерн ко всем картинкам года.

Если в официальном PDF рядом с рисунком расположена таблица, список характеристик или иной самостоятельный смысловой блок, решение принимается **по конкретному заданию**: либо отдельный direct source crop, либо точная HTML-структура из официального текста, если это не является реконструкцией самого визуала. В audit record фиксируется источник каждого элемента.

Для крупного/мелкодетального визуала обязательны:

- адекватный базовый размер в интерфейсе;
- увеличение по клику/тапу;
- zoom in / zoom out / reset;
- mobile-проверка увеличенного режима;
- отсутствие потери подписей при масштабировании.

`VISUAL_UI_CROP_GATE = PASS` запрещён без поштучной проверки всех visual assets.

## 8. Правило официальных примеров «ИЛИ»

Каждый официальный пример внутри одной позиции проверяется отдельно. «ИЛИ» — структура официального документа, а не выбор ученика. Система назначает один официальный пример и сохраняет его после reload.

## 9. Поля ответа и controls

Тип контрола определяется действием ученика в конкретном официальном примере:

- краткий ответ → input;
- соответствие → отдельные select под элементами соответствия;
- «выберите все» → checkbox;
- один вариант → radio/select;
- заполнение структуры → поля/select в структуре;
- развёрнутое решение → textarea/поле решения.

Запрещено заменять официальное действие универсальным полем «введите последовательность» только потому, что в бланке итог кодируется цифрами.

## 10. Browser interaction audit

Каждый официальный пример реально открывается и выполняется через DOM-controls. Проверяются: неполный/полный ответ, изменение, очистка, правильный и неправильный ответ, допустимые альтернативы, autosave, reload, восстановление назначенного примера и ответа, навигация и завершение.

Прямая запись в state/localStorage не считается interaction-test.

## 11. Scorer

Scorer проверяется после interaction audit. Для каждого примера обязательны правильный и неправильный кейс, а также только официально допустимые эквиваленты/альтернативы. Matching получает код из отдельных выборов, multiple choice — множество выбранных элементов.

## 12. Справочные материалы

Справочные материалы должны быть именно соответствующего года. Если они переносятся изображением — это direct source render/crop. Они проходят те же source-origin и desktop/mobile readability проверки.

## 13. State / timer / navigation / results

Проверяются старт, таймер, Следующее/Предыдущее, переход по номерам, отметка для возврата, статусы навигации, autosave, reload, восстановление варианта и ответа, очистка, завершение и итоговый экран.

Итоговый экран должен показывать минимум: ответ ученика, официально принимаемый ответ/критерий в допустимой форме и начисленный балл.

## 14. T123 ATOMIC GATE — урок регрессии 2024

**Запрещено механически разрезать готовый HTML/JS/base64 по количеству байт.**

Каждый T123 должен быть самостоятельным синтаксически закрытым фрагментом. Между T123 нельзя переносить незакрытое состояние HTML/JS/CSS.

Обязательные правила:

1. разделение только по безопасным границам законченных HTML / `<style>...</style>` / `<script>...</script>` блоков;
2. длинный base64 делится заранее на части, каждая часть помещается в отдельный полностью закрытый `<script>...</script>`, который добавляет chunk в общий массив;
3. запрещено начинать T123 с продолжения строкового литерала/base64 предыдущего T123;
4. запрещено заканчивать T123 незакрытым `<script>`, `<style>`, HTML-тегом, JS-строкой, template literal или комментарием;
5. **каждый T123 проверяется отдельно**, а не только после общей склейки;
6. дополнительно проверяется склейка `T123-01 ... T123-N` строго по порядку;
7. после любого изменения разделения — полный browser regression;
8. формируется `T123-MANIFEST` с номером, размером и SHA-256 каждого T123, чтобы при исправлении можно было доказать, какие блоки реально изменились и не заставлять перезаливать неизменные.

Внутренний консервативный порог: **< 42 500 байт на T123**, если year-specific package contract не задаёт ещё меньший лимит.

`TILDA_T123_ATOMIC_GATE = PASS` и `TILDA_SIZE_GATE = PASS` обязательны перед выдачей архива.

## 15. Change control

После правки обязателен diff до/после. Повторно прогоняются все gates, которых касается изменение. Изменение общего renderer/control требует regression всех типов, которые его используют. Изменение crop требует source fidelity + visual UI crop + responsive/zoom regression этого asset и связанных вариантов.

## 16. Clean ZIP gate

Финальный ZIP замораживается и распаковывается в **новую чистую папку**. Из чистой распаковки повторяются:

- source traceability;
- formula gate;
- source visual fidelity;
- visual UI crop inventory consistency;
- T123 standalone atomicity;
- T123 sequence/size/manifest;
- browser interaction;
- state/reload;
- responsive;
- zoom;
- package integrity.

Тест рабочей папки без clean-ZIP regression недостаточен.

## 17. Responsive и visual classes

Минимальные контрольные ширины: 1280, 768, 390, 360, 320 px. Проверяются horizontal overflow и читаемость всех классов визуалов: график, план/схема, геометрия, таблица, формула, числовая прямая/координатный визуал, крупный zoomable asset.

Один screenshot одного задания не закрывает visual regression всего года.

## 18. READY_FOR_TILDA и LIVE_GO

`READY_FOR_TILDA` разрешён только после PASS всех применимых gates, включая SOURCE, TEXT/TYPOGRAPHY, FORMULA, VISUAL_SOURCE, VISUAL_UI_CROP, INTERACTION, SCORER, STATE, T123_ATOMIC, T123_SIZE, CLEAN_ZIP и independent audit.

`LIVE_GO` — только после фактической публикации, production smoke на живой странице и ручной ученической приёмки.

Предыдущие PASS/READY другого пакета или года не являются доказательством.

## 19. Главный запрет

**Нельзя называть математическую демоверсию проверенной, пока не доказано, что каждый официальный пример одновременно совпадает с официальным источником, визуалы происходят только из источника и правильно откадрированы для интерфейса, ученик получает правильный контрол, T123 атомарны и валидны, а финальный clean ZIP реально проходит браузерную проверку.**
