# Уроки исправленных демоверсий

Этот файл связывает реальные дефекты с их первопричинами и обязательными защитами для новых предметов.

## 1. Базовая математика: лишние правильные ответы

### Дефект

В заданиях были добавлены ответы, которых нет в финальной таблице ФИПИ. Ошибка затем размножилась в T123, README, SOURCE GATE, карте заданий, аудите и тестовом отчёте.

### Первопричина

- ручной список `acceptedAnswers`;
- старое предположение было принято за факт;
- документация копировалась из данных, но не генерировалась из единого источника;
- тесты проверяли, что добавленный ответ принимается, а не что он подтверждён источником.

### Защита

- каждый accepted answer имеет `source_locator`;
- альтернативный ответ без source locator запрещает сборку;
- обязательный негативный тест для каждого правдоподобного неподтверждённого ответа;
- TEST-REPORT генерируется только после тестов;
- документация не хранит независимые списки ответов.

## 2. Профильная математика: искажённые критерии

### Дефект

Сокращённые описания меняли официальные основания частичного балла. Самооценка пользователя прибавлялась к общему результату.

### Первопричина

- критерии пересказывались общими словами;
- тестировались максимумы, но не каждая ветвь частичного балла;
- интерфейс смешал учебную самооценку и официальный результат;
- использовался проектный PDF в цепочке приёмки.

### Защита

- критерии хранятся по баллам и альтернативным ветвям;
- каждая ветвь содержит страницу PDF;
- для каждого балла есть отдельный тест;
- `expert_only` не может изменять официальный total;
- проектные PDF запрещены release-gate;
- финальные PDF обязательно включаются в source и manifest.

## 3. Русский язык: технический счётчик стал официальным правилом

### Дефект

Технический счётчик слов использовался как автоматический официальный порог. Неправильные краткие ответы с посторонними символами очищались до правильных.

### Первопричина

- эвристика была принята за официальный алгоритм;
- нормализатор удалял ошибки пользователя;
- были реализованы не все общие основания нуля;
- тесты проверяли 149 слов, но не пограничные сокращения и неавторские слова.

### Защита

- технический счётчик всегда advisory-only;
- официально неавтоматизируемые основания подтверждаются отдельно;
- любые лишние символы сначала отклоняются, а не удаляются;
- обязательные тесты: сокращения, пробелы, буквы в цифрах, общий ноль, частичное переписывание;
- K1-зависимость защищается и в UI, и в расчёте.

## 4. Физика: правильный текст, неправильный рисунок

### Дефект

Текст решения и ответ были верными, но эталонные SVG показывали неправильное положение объекта, направления сил и степень погружения. Отдельные SVG и встроенные копии могли расходиться.

### Первопричина

- рисунок считался иллюстрацией, а не частью ответа;
- SVG проверялся визуально поверхностно;
- встроенная копия редактировалась отдельно;
- тесты не проверяли геометрические и физические инварианты.

### Защита

- для каждого SVG создаётся `ASSET-MAP` с предметными инвариантами;
- встроенный SVG генерируется из отдельного файла;
- хеш/строка отдельной и встроенной версии должны совпадать;
- проверяются координаты, оси, симметрия, стрелки, подписи и обязательные силы;
- обязательна независимая визуальная сверка с PDF.

## 5. Обществознание: зависимый критерий можно было обойти

### Дефект

Критерий 24.2 мог быть выбран и суммирован при недостаточном значении 24.1. В задании 25 до ответа показывалось неполное условие. Дополнительные символы очищались до правильного ответа.

### Первопричина

- зависимость защищалась только частично;
- полное условие находилось в guide после завершения, а не в prompt;
- scoring engine доверял состоянию интерфейса;
- нормализация была permissive;
- тесты не проверяли последовательности изменения зависимых полей.

### Защита

- зависимость реализуется дважды: UI + scorer;
- полный официальный prompt показывается до ввода ответа;
- тестируются все переходы зависимых значений;
- scorer не доверяет сохранённому состоянию;
- строгая форма ответа является значением по умолчанию.

## 6. Общие упаковочные дефекты

### Дефекты

- PDF не входили в manifest;
- тесты использовали абсолютные пути;
- служебный текст попадал в интерфейс;
- старые отчёты сохраняли PASS после изменения данных;
- локальный PASS выдавался за опубликованную готовность;
- production URL мог возвращать 404.

### Первопричины

- manifest собирался не последним;
- release ZIP формировался из рабочего каталога;
- отчёты редактировались вручную;
- не было строгой системы статусов;
- production smoke-test не был самостоятельным gate.

### Защита

- белый список release-файлов;
- manifest создаётся последним;
- тесты запускаются из распакованного ZIP относительными путями;
- отчёт генерируется из фактических результатов;
- `READY_FOR_TILDA_TEST` и `PUBLISHED_SMOKE_PASS` — разные статусы;
- HTTP 404 автоматически блокирует публикационный PASS.

## 7. Биология и история: scorer работал, но задание нельзя было выполнить в интерфейсе

### Дефект

Задания на соответствие, последовательность, заполнение таблицы и множественный выбор были сведены к одному текстовому полю. Тест подставлял готовый цифровой код, подтверждал сохранение и начисление баллов и выставлял PASS, хотя ученик не мог выполнить требуемое действие непосредственно в интерфейсе.

### Первопричина

- тип задания определялся как общий `short`, а не как конкретное действие;
- UI и scorer не имели общего interaction contract;
- browser-тест использовал canonical answer как готовую строку;
- наличие input ошибочно считалось доказательством интерактивности;
- незавершённое структурированное состояние не тестировалось.

### Защита

- для каждой позиции создаётся `INTERACTION-CONTRACT`;
- таблицы, соответствия, последовательности и множества получают типизированные controls;
- код для бланка собирается автоматически;
- незавершённое состояние сохраняется, но не считается готовым;
- browser-тест выполняет задание реальными кликами и селектами;
- отдельный метатест запрещает выпуск, если сложное действие заменено одним текстовым полем;
- правило применяется ко всем предметам независимо от названия дисциплины.

## 8. Системная первопричина

Во всех предметах повторяется один паттерн:

> данные, критерии, рисунки, тесты и отчёты поддерживались как несколько независимых версий одного и того же факта.

Поэтому главное изменение процесса — не «проверять внимательнее», а **устранить ручные дубли**.

Новый пакет должен собираться так:

```text
Финальные PDF ФИПИ
        ↓
SOURCE REGISTER + EXAM MAP + TASK MAP + ASSET MAP
        ↓
независимая содержательная блокировка
        ↓
автоматическая генерация T123 / preview / tests / manifest / ZIP
        ↓
локальный release-gate
        ↓
публикация Tilda
        ↓
production smoke-gate
```

Чем меньше фактов можно изменить вручную после CONTENT LOCK, тем ниже риск повторения ошибок.

## Русский язык: сочинение и post-exam review — 2026-08-15

Финальная доводка 2026 v4.2 показала, что зелёный scorer недостаточен без полного UX/state-аудита развёрнутого ответа. Зафиксированы обязательные уроки:

- не показывать ученику внутреннюю терминологию analyzer;
- не запускать проверку во время перепечатки, если интерфейс обещает явную кнопку проверки;
- после редактирования инвалидировать предыдущие findings/scores;
- внешний status хранить в namespace текущей попытки, иначе новая попытка может наследовать старое «проверено»;
- итоговый status должен учитывать все локальные и внешние advisory-сигналы, а не только ответ одного API;
- нулевой результат analyzer формулировать как «ничего не отмечено», а не «ошибок нет»;
- для бумажного сочинения поддерживать несколько страниц, увеличение и честно описывать отсутствие persistence файлов;
- после полной самооценки показывать ученику общий учебный результат, а не оставлять общий балл неопределённым;
- installation, manifest, after-publish checklist и browser tests должны обновляться вместе с runtime-архитектурой.
