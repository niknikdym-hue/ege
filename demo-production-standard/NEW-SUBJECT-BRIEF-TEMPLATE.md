# Шаблон задания на новую интерактивную демоверсию

Скопировать, заполнить значения в угловых скобках и передать исполнителю.

---

Создай полный пакет интерактивной демоверсии ЕГЭ по предмету **<ПРЕДМЕТ>** для страницы:

`https://eksamio.ru/ege/<SLUG>/demoversiya/`

Префикс файлов:

`ege-<SLUG>-demoversiya`

Работай по стандарту `demo-production-standard/README.md`.

## Источники

Используй только финальный официальный комплект ФИПИ:

- демонстрационный вариант;
- спецификацию;
- кодификатор.

Сохрани три файла локально в `source/`, зафиксируй SHA-256 и точные страницы для условий, ответов, критериев и изображений.

Не используй образовательные сайты, пособия, старые версии, проектные PDF и материалы конкурентов как подтверждение формата.

Если утверждение не подтверждено финальными документами, зафиксируй:

`НЕ ПОДТВЕРЖДЕНО — ТРЕБУЕТ ПРОВЕРКИ`

и не включай его в рабочую демоверсию.

## Обязательная последовательность

1. SOURCE GATE.
2. EXAM MAP.
3. TASK MAP для всех позиций и вариантов «ИЛИ».
4. ASSET MAP для всех официальных изображений.
5. ACCEPTANCE CASES с позитивными и негативными тестами.
6. Независимая содержательная сверка.
7. Автоматическая сборка T123, preview, manifest и ZIP.
8. Unit и browser-тесты.
9. Release-gate.

Не создавай T123 до статуса `CONTENT_LOCKED`.

## Правила ответов

- По умолчанию любой лишний символ даёт 0.
- Не удаляй буквы, пробелы, запятые и знаки до проверки.
- Порядок игнорируй только там, где это прямо разрешено ФИПИ.
- Альтернативный ответ добавляй только с точной страницей официального источника.
- Для каждого официального и альтернативного ответа создай позитивный тест.
- Для каждого задания создай негативные тесты с лишним пробелом, знаком, буквой, цифрой, пропуском и повтором.

## Развёрнутые задания

- Передай точные смысловые ветви критериев для каждого балла.
- Не сокращай критерии общими фразами.
- Каждая ветвь должна иметь страницу PDF и отдельный тест.
- Все зависимости реализуй и в UI, и в функции подсчёта.
- Учебная самооценка не является официальным результатом и не должна автоматически формировать официальный итог.
- Технические эвристики не используй как официальные основания.

## Изображения

- Каждый официальный рисунок сверяй с PDF.
- Зафиксируй предметные инварианты.
- Храни один канонический SVG.
- Встраивай его в T123 автоматически.
- Проверяй идентичность отдельной и встроенной версии.

## Интерфейс

Сохрани фиксированную навигацию Эксамио:

- зелёный — ответ сохранён;
- оранжевый — отмечено для возврата;
- белый — ответа нет;
- синяя рамка — открытое задание.

Обязательны таймер, предыдущий/следующий номер, отметка для возврата, сброс и завершение.

Постоянный URL, canonical, Title, Description, Keywords и slug не содержат год. Год допускается в интерфейсе конкретной актуальной демоверсии и внутренних метаданных источника.

## Обязательные файлы

Состав пакета — строго по `demo-production-standard/README.md`.

Все служебные файлы находятся на одном уровне с T123. Не создавай отдельную папку `00-source-gate/`.

## Обязательные тесты

- все официальные примеры;
- все варианты «ИЛИ»;
- все альтернативные ответы;
- все ветви частичных баллов;
- все зависимости;
- все общие основания нуля;
- неверные формы ввода;
- полный максимум;
- сохранение и восстановление;
- непрерывный таймер;
- 320/360/390/768/1280 px;
- отсутствие горизонтального скролла;
- отсутствие ошибок консоли;
- целостность manifest и ZIP;
- запуск тестов из распакованного ZIP относительными путями.

## Статус

До проверки реальной опубликованной страницы максимальный допустимый статус:

`READY_FOR_TILDA_TEST`

Не заявляй production PASS до публикации и отдельного smoke-test на Tilda.

## Результат

Не выводи промежуточные SOURCE GATE, служебные архивы и длинные пояснения, если они отдельно не запрошены.

Выполни полный цикл и передай:

1. один готовый ZIP;
2. краткий итоговый статус;
3. честный список того, что остаётся проверить после публикации в Tilda.
