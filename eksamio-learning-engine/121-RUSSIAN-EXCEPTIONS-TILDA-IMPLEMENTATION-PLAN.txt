RUNTIME DATA DELIVERY — MEASURED DECISION FOR STANDALONE EXCEPTIONS

INPUT:
`audits/RUSSIAN-RUNTIME-SIZE-AUDIT.txt`

MEASURED CURRENT EXCEPTIONS RUNTIME:
- current validated runtime contains 73 enabled exceptions and 80 practice items;
- gzip size is irrelevant for raw T123 editor limits;
- standalone first release should avoid an unnecessary external runtime-host dependency.

CURRENT STANDALONE DECISION:
- use deterministic T123 JSON chunks for Exceptions Runtime;
- chunks are data only;
- validated builder output: 3 data-only T123 chunks; largest block 34,875 UTF-8 bytes INCLUDING the application/json wrapper;
- hard project safety ceiling remains below the accepted ~42.5 KiB/block boundary;
- every chunk carries the same content version, sequence index and expected chunk count;
- bootstrap fails closed if a chunk is missing, duplicated or from another version.

This decision applies ONLY to the standalone Exceptions Trainer.
The larger Explanation Runtime is a separate later integration decision.

OPTION A — HOSTED STATIC JSON
Reserved for a future case where runtime payload or release workflow makes T123 data chunks cumbersome.

Advantages:
- small T123 code;
- runtime data can be versioned separately;
- browser caching;
- cleaner source/data separation.

Requirements:
- stable HTTPS asset location controlled by project;
- version/integrity check;
- CORS/cache behavior verified;
- previous validated runtime retained for rollback.

OPTION B — T123 JSON CHUNKS
Use only if measured payload size makes this practical.

Rules:
- split generated data deterministically;
- each block below the project safety margin, not merely Tilda hard failure point;
- chunks have content version + sequence + expected count;
- loader refuses incomplete/mixed-version chunk set;
- chunks contain data only, not duplicate UI/engine code.

OPTION C — HYBRID
- small bootstrap/topic/index inline;
- larger practice payload hosted.

Do not choose A/B/C before actual size audit.
