PURPOSE

Назначать source-driven `launch_priority` для выбора новых исключений в сессии без субъективного ранжирования «лёгкое/сложное».

PRIORITY ENUM

P0 CURRENT_DIRECT
P1 RECENT_OR_REPEATED
P2 CORE_RULE_CONTRAST
P3 REFERENCE_LOW_LAUNCH

This priority is for content scheduling only.
It is NOT learner difficulty and must never populate a difficulty field.

EVIDENCE INPUTS

Allowed evidence:
- current 2026 trainer/demo exact item/word/context;
- verified official current list/codifier/spec where applicable;
- multiple recent trainer/demo years;
- current standalone verified source bank when that bank is itself official-source-derived;
- Rosenthal core rule/exception relation linked to accepted EGE skill/subskill;
- explicit historical-only/legacy status.

Not allowed:
- intuition that a word is common;
- web popularity;
- teacher anecdote;
- guessed exam frequency;
- item difficulty estimated from spelling appearance.

P0 — CURRENT_DIRECT

Assign only when the exception/special case is directly represented in a current 2026 product/official current list.

Required metadata evidence example:
- source_type `existing_trainer` + locator explicitly identifies current 2026 card/word;
OR
- official current normative list entry.

P0 examples conceptually include current task forms/contrasts that are explicitly present, but actual IDs must be generated by evidence scan rather than hand-labeled from memory.

P1 — RECENT_OR_REPEATED

Assign when:
- same exception/contrast appears in >=2 accepted recent trainer/demo years;
OR
- item is in an accepted current supporting bank and repeatedly maps to recent product material;
OR
- it is a verified high-value historical/current transition case still relevant to the current accepted skill.

Historical occurrence alone does not automatically mean P1 if the format/rule has changed.

P2 — CORE_RULE_CONTRAST

Assign when:
- source is Rosenthal/verified language norm;
- linked to an accepted current EGE skill/subskill;
- not directly evidenced as current/repeated enough for P0/P1;
- pedagogically useful for distinguishing rule vs exception or homonymous constructions.

This is the default for strong source-only exceptions that remain relevant to the current exam skill.

P3 — REFERENCE_LOW_LAUNCH

Assign when:
- rare reference exception;
- weak/no current product evidence;
- historical or specialized vocabulary with low immediate EGE route value;
- still normatively valid and useful for reference/long-term bank.

P3 does not mean «unimportant forever».
Learner personal error on a P3 item overrides launch priority in My Exceptions/due queues.

PERSONAL STATE OVERRIDES

Selection priority order always treats:
- due retention;
- unresolved personal error;
- failed transfer;
- exact handoff
as stronger than source launch P0–P3.

A P3 personal error can outrank a new P0 item.

GENERATION ALGORITHM — FUTURE BUILD

For each canonical exception_id:
1. collect all source_refs;
2. resolve existing_trainer locators to current/recent/historical evidence where structured metadata exists;
3. resolve official current list membership if applicable;
4. count distinct recent source years only from accepted provenance, not prompt text parsing alone;
5. apply deterministic rules P0 -> P1 -> P2 -> P3;
6. store `priority_reason_codes` and evidence refs;
7. never overwrite manual review HOLD/legacy exclusions.

PRIORITY REASON CODES

- current_2026_trainer_exact
- current_official_list
- repeated_recent_years
- current_supporting_bank
- core_rozental_current_skill
- historical_only
- rare_reference_case
- personal_override_runtime (runtime only; not content metadata)

OUTPUT CONTRACT — FUTURE

Separate overlay preferred:
`build/RUSSIAN-EXCEPTIONS-LAUNCH-PRIORITY.json`

Each row:
{
  exception_id,
  launch_priority,
  priority_reason_codes,
  evidence,
  status
}

Do not rewrite source exception banks merely to attach derived scheduling metadata.

VALIDATION

- every exception_id resolves to canonical Exceptions Bank;
- exactly one launch_priority per enabled exception;
- P0 has current evidence;
- P1 has repeated/recent evidence;
- P2 has accepted current skill/subskill + source rule;
- P3 remains source_verified;
- legacy format mismatch cannot be promoted P0 from an old item;
- no difficulty field generated.

SPECIAL CASES

ORTHOEPY
Current official/source-derived bank membership can support high launch priority, but full 96-entry bank is still not duplicated into Exceptions Trainer.

PARONYMS
Full paronym bank remains separate. Exception launch priority applies only to selected contrast IDs included in Exceptions Bank.

TASK 25 HISTORICAL SYNONYM
Must remain legacy-separated and must not become current P0 merely because its task number is 25.
