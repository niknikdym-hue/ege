КОНТЕКСТ

Текущий тренажёр русского языка был собран Codex как итог работы над всеми демоверсиями ЕГЭ по русскому языку, а не как независимый отдельный продукт.
Поэтому при построении Skill Graph нельзя исходить только из одной текущей демоверсии.

ИСТОЧНИКИ ДЛЯ АУДИТА И ПОСТРОЕНИЯ ГРАФА, В ПОРЯДКЕ ПРИОРИТЕТА:
1. Фактическая текущая структура тренажёра русского языка в репозитории.
2. Все текущие и архивно-рабочие материалы по демоверсиям русского языка, из которых тренажёр был сформирован.
3. Текущая опубликованная/актуальная демоверсия русского языка как контроль соответствия экзаменационной нумерации.
4. Проверенные source-gate / task-map / answer-map / criteria / implementation файлы, если они есть в текущем репозитории.

ГЛАВНЫЙ ПРИНЦИП

Skill Graph должен описывать уже существующий продукт и проверенную предметную структуру.
Нельзя менять продукт ради удобства Skill Graph.

ЦЕЛЬ ЭТАПА

Создать фактическую карту:

так, чтобы в будущем демоверсия могла передать найденную слабость в тренажёр без изменения текущей экзаменационной логики.

--------------------------------------------------
1. 03-RUSSIAN-SKILL-GRAPH.json
--------------------------------------------------

Файл должен быть валидным JSON UTF-8.

Минимальная верхнеуровневая структура:

{
  "schema_version": "1.0.0",
  "subject": "russian",
  "exam": "ege",
  "source_status": "repository-audited",
  "generated_from": [],
  "skills": [],
  "task_links": [],
  "trainer_links": [],
  "review_queue": []
}

Для каждого skill:

{
  "skill_id": "stable-machine-id",
  "name_ru": "...",
  "parent_skill_id": null,
  "description": "...",
  "exam_task_numbers": [],
  "prerequisites": [],
  "evidence_status": "confirmed|partial|needs_review"
}

ТРЕБОВАНИЯ К skill_id:
- стабильные;
- машинно читаемые;
- без года;
- без привязки к конкретной версии демоверсии;
- не менять смысл ID при будущих обновлениях;
- отдельный ID только там, где реально существует отдельный диагностируемый навык.

Для task_links:

{
  "task_number": 4,
  "task_id": "...",
  "skill_ids": [],
  "subskill_ids": [],
  "evidence": [],
  "status": "confirmed|partial|needs_review"
}

Для trainer_links:

{
  "trainer_item_id": "...",
  "source_path": "...",
  "exam_task_numbers": [],
  "skill_ids": [],
  "subskill_ids": [],
  "difficulty": null,
  "status": "confirmed|partial|needs_review"
}

IMPORTANT ABOUT DIFFICULTY:
- если в текущих данных нет валидной измеренной сложности — difficulty MUST be null;
- не использовать субъективные low/medium/high;
- не вычислять псевдосложность из одного наблюдения.

PREREQUISITES:
- добавлять только если связь можно обосновать фактической предметной структурой;
- сомнительную связь не фиксировать как факт;
- использовать needs_review.

--------------------------------------------------
2. 03A-RUSSIAN-SKILL-GRAPH-PROVENANCE.txt
--------------------------------------------------

Для каждого крупного блока Skill Graph указать:
- какие фактические файлы репозитория использованы;
- путь;
- что именно из них взято;
- текущий статус источника;
- есть ли конфликт между источниками;
- какое решение принято;
- если решение невозможно без предметного аудита — пометить NEEDS_REVIEW.

ОБЯЗАТЕЛЬНО отдельно описать:
- как текущий тренажёр связан с ранее созданными демоверсиями русского;
- какие номера ЕГЭ реально представлены в тренажёре;
- где тренажёр имеет более детальное разбиение, чем одна нумерация задания;
- где одной ошибки в номере ЕГЭ недостаточно, чтобы определить subskill.

--------------------------------------------------
3. 03B-RUSSIAN-SKILL-GRAPH-VALIDATION.txt
--------------------------------------------------

Дать независимую проверку полученного графа.

Минимальные проверки:

A. NO-DESTRUCTIVE-CHANGE CHECK
Подтвердить, что существующие файлы проекта не изменены.

B. JSON VALIDATION
03-RUSSIAN-SKILL-GRAPH.json парсится без ошибок.

C. TASK COVERAGE
Показать покрытие текущих заданий русского языка:
- confirmed;
- partial;
- needs_review.

D. TRAINER COVERAGE
Сколько фактических trainer items / групп / наборов удалось связать со skills.

E. ORPHAN CHECK
- skill без task/trainer links;
- task без skill;
- trainer item без skill.

F. ID STABILITY CHECK
Нет ID, завязанных на 2026 или конкретный архив/версию.

G. SOURCE CONFLICT CHECK
Все найденные расхождения перечислены; ничего не исправлено молча.

H. FUTURE HANDOFF READINESS
Для каждого экзаменационного задания определить:
- можно ли после ошибки безопасно отправить ученика в точный trainer pool;
- можно ли отправить только в общий pool задания;
- требуется дополнительная диагностика subskill.

КЛАССЫ HANDOFF READINESS:
- exact
- task_level_only
- diagnostic_required
- unavailable

--------------------------------------------------
ОСОБЕННО ВАЖНО
--------------------------------------------------

1. НЕ считать, что номер задания автоматически равен одному skill.

2. НЕ считать, что тренажёр создан независимо от демоверсий.
Тренажёр — результат предыдущей работы Codex над русскими демоверсиями и должен рассматриваться как важный синтезированный источник текущей структуры.

3. НЕ менять сам тренажёр, если его текущая внутренняя структура неудобна для графа.
Граф адаптируется к фактическому продукту, не наоборот.

4. НЕ смешивать official/source-of-truth exam facts и аналитические inference.
Для каждого спорного вывода нужен status=needs_review.

5. НЕ начинать с AI.
Цель этого этапа — детерминированная предметная карта.

6. НЕ создавать paywall или изменения UX.
Базовый learning loop остаётся бесплатным.

7. НЕ создавать новый банк заданий.
Работать с существующими проверенными материалами.

8. НЕ ухудшать и не сокращать существующую функциональность.
