Зафиксированные положения:

- квалификация речевых и ряда других ошибок требует контекста;
- эксперт учитывает нормативные варианты, переходные случаи и двоякую квалификацию;

ПОЛИТИКА CONFIRMED
Встроенный regex-анализатор является только предварительной автоматической проверкой. Он не умеет надёжно установить цитирование, метаязыковое употребление, авторскую функцию повтора, ключевую лексику, полную синтаксическую структуру и нормативные исключения. Поэтому НИ ОДНО встроенное правило analyzeEssayText() не создаёт confirmed finding. Confirmed допускается только как результат отдельной однозначной проверки. Только confirmed влияет на hard cap.

АУДИТ ПРАВИЛ
1. «вообщем», «вобщем», «какбудто», «изза» → POSSIBLE K7. Regex не отличает собственное употребление от цитирования/метаязыкового примера.
2. Смешение кириллицы и латиницы → POSSIBLE K7. Требуется ручная проверка конкретного токена.
3. «ихний» и словоформы → POSSIBLE K9. Возможны цитирование, передача чужой речи, разбор ошибки.
4. Два одинаковых соседних слова → POSSIBLE K10, никогда не confirmed автоматически. Требуется контекст и оценка функции повтора.
5. Одно слово 3+ раз в одном абзаце → POSSIBLE K10, никогда не confirmed автоматически. Повторы между абзацами не агрегируются.
6. Повторяющиеся ?/! → POSSIBLE K8. Нужна контекстная проверка оформления.
7. Нет завершающего знака в конце введённого текста → POSSIBLE K8. Ввод может быть незавершённым/фрагментарным.
8. Пробел перед уже поставленным знаком → TECHNICAL. Не К8, не finding К7–К10, hard cap не создаёт.

ОБЯЗАТЕЛЬНЫЕ ИНВАРИАНТЫ
- possible не меняет cap и не превращается автоматически в confirmed;
- technical не относится к К7–К10 и не влияет на балл;
- отсутствие findings не означает отсутствия ошибок и не выставляет автоматически 3;
- значение выше confirmed cap отклоняется UI и scorer;
- шкала задания 27 только 0–22;
- встроенная проверка явно названа предварительной и не заменяющей эксперта.

РЕГРЕССИИ
- «Это это было важно» → confirmed K10 = 0; possible K10 допустим;
- стилистический/ключевой повтор → confirmed K10 = 0;
- повтор между абзацами не агрегируется;
- «Это пример , текста.» → K8 finding = 0; technical notice = 1;
- built-in preliminary analyzer → confirmed total = 0;
- validated external confirmed → hard cap по официальной шкале.

Итог: правила analyzeEssayText() допустимы как консервативный предварительный слой и не заявляются как экспертная проверка. Содержательный NO-GO закрыт.
