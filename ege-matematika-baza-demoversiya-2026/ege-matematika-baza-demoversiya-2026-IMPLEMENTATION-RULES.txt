IMPLEMENTATION RULES — ЕГЭ 2026, МАТЕМАТИКА, БАЗОВЫЙ УРОВЕНЬ
PACKAGE_VERSION: 1.0
STATUS: DRAFT_UNTIL_CONTENT_LOCK

1. ИСТОЧНИК
— Только финальный комплект ФИПИ 2026 из SOURCE-REGISTER.
— Старые математические демоверсии, ZIP, scorer и preview не являются источником данных.
— Официальный текст задания не сокращается, не перефразируется и не «улучшается».
— Формулы и предметный визуал проходят отдельный SOURCE ↔ DEMO gate.

2. ОФИЦИАЛЬНЫЕ ПРИМЕРЫ «ИЛИ»
— На старте новой попытки для каждой позиции автоматически назначается один официальный пример ФИПИ.
— Ученик не выбирает между примерами «ИЛИ».
— Номер назначенного примера сохраняется в state/localStorage и не меняется после reload.
— Новая попытка получает новый набор вариантов.
— Каждый из 70 официальных примеров должен иметь отдельный acceptance/browser-test.

3. ТИПЫ КОНТРОЛОВ
— numeric_input: краткий ответ, который ученик должен записать числом/последовательностью цифр.
— matching_selects_4: четыре отдельных select под А/Б/В/Г; итоговый код собирает система.
— checkboxes: «выберите все утверждения»; итоговый набор собирает система.
— row_checkboxes: выбор строк/объектов из таблицы; итоговый набор собирает система.
— Нельзя заменять matching/selection универсальным полем «введите код».

4. NUMERIC INPUT — INPUT HYGIENE
Scorer работает только со строгой канонической строкой и не «очищает» ошибочный ответ.
Разрешено интерфейсом ДО сохранения:
— цифры 0–9;
— один ведущий знак минус, если он нужен конкретному ответу;
— одна десятичная запятая;
— клавиатурная точка может быть немедленно заменена в поле на запятую до сохранения (UX-канонизация; отдельный тест обязателен).
Запрещены и не должны тихо удаляться:
— пробелы внутри ответа;
— буквы;
— единицы измерения;
— плюс;
— несколько запятых/точек;
— любые иные знаки.
Пробелы не превращаются scorer-ом в правильный ответ.
Ведущие нули, лишние конечные нули и иные формы не принимаются, если их нет среди подтверждённых canonical_forms.
Печатный пробел-разделитель тысяч в таблице ФИПИ не вводится: 12 200 → canonical 12200.

5. MATCHING
— Для А, Б, В, Г показываются отдельные controls рядом с соответствующими позициями ответа.
— Нельзя выбрать один и тот же номер дважды, если структура конкретного задания предполагает взаимно однозначное соответствие; UI должен предотвращать дубликаты или явно показывать невалидность.
— Статус «ответ дан» появляется только когда заполнены все четыре позиции валидными значениями.
— Scorer получает код, собранный системой в порядке А-Б-В-Г.

6. CHECKBOX / ROW CHECKBOX
— Неполный или пустой набор не считается заполненным ответом.
— Для №8 порядок выбора не влияет на результат; scorer сравнивает множество.
— Для №6 варианты 1–2 scorer сравнивает множество выбранных строк с подтверждёнными допустимыми наборами, а не строковые перестановки.
— Итоговый код для отчёта формирует система.

7. SCORER
— Единственный источник официальных ответов: OFFICIAL-ANSWERS.json.
— По умолчанию полное точное совпадение = 1, иначе 0.
— Частичных баллов в базовой работе 2026 нет.
— Никакие «логически эквивалентные» дополнительные ответы не добавляются без прямого подтверждения ФИПИ.
— Нельзя использовать value.replace(/\D/g, "") и аналогичную очистку.

8. СОСТОЯНИЕ И НАВИГАЦИЯ
— Новый storage key: eksamio_ege_math_base_demo_2026_v1_0.
— Сохраняются: attempt id, назначенные варианты 1–21, ответы, отметки для возврата, текущая позиция, время окончания, статус завершения.
— autosave после каждого валидного изменения.
— reload восстанавливает именно тот же вариант и тот же ответ.
— невалидный ввод не должен давать зелёный статус «ответ сохранён».
— цвета навигации: зелёный — валидный ответ; оранжевый — отмечено для возврата; белый — ответа нет; синяя рамка — открытое задание.

9. ТАЙМЕР И ЗАВЕРШЕНИЕ
— 180 минут по EXAM-MAP.
— Оставшееся время вычисляется по сохранённому deadline, а не уменьшаемому локальному счётчику.
— Проверка результата доступна только после завершения попытки.
— По истечении времени попытка завершается автоматически.
— Итог: первичный результат 0–21. Не придумывать перевод во вторичный/тестовый балл без отдельного официального источника и продуктового решения.

10. ВИЗУАЛЫ И ФОРМУЛЫ
— Графики, планы, геометрические рисунки и иные предметные изображения должны происходить из официального PDF либо быть реконструированы только после отдельной source-fidelity проверки.
— Для каждого визуала: четыре края, подписи, оси, деления, числа, точки, линии, легенда, единицы, геометрические отношения.
— Формула сверяется семантически и визуально. Математически эквивалентная перезапись не заменяет literal fidelity.
— Справочные материалы 2026 доступны отдельным интерфейсом и воспроизводятся только по официальному источнику.
— Не заявлять наличие виртуальной линейки. На экзамене линейка разрешена; в продукте отдельный виртуальный инструмент появляется только если он реально реализован и протестирован.

11. UI/UX
— Светлый фирменный стиль Эксамио; не копировать бумажный бланк как интерфейс целиком.
— Официальный текст задания визуально отделён от интерфейсных подсказок Эксамио.
— Все controls имеют label/aria-label и доступны клавиатурой.
— Mobile gate: 320, 360, 390 px; также 768 и 1280 px.
— Горизонтальный скролл страницы запрещён; отдельный скролл большой таблицы допускается только если неизбежен и протестирован.

12. TILDA / T123
— Шапка и футер подключаются отдельно и не входят в локальный код демоверсии.
— Каждый T123 < 45 000 байт (внутренний консервативный порог проекта).
— После любого разбиения/переноса кода — полный browser regression.
— Порядок T123 фиксируется в EXAM-MAP и INSTALLATION.
